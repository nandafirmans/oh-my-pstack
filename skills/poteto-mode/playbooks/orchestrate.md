### Orchestrate

**You run the program, never the code. Decide who does each unit, then check what each produces.** For a standing project spanning days, many PRs, and many delegated sessions. One task driven to a predicate is **Autonomous run**. One ambitious bespoke run is **figure-it-out**. Work one session can finish is not a program.

Use the active adapter's canonical protocols and native completion events. Keep the objective, standing orders, briefs, participant records, PR heads, verdicts, gates, and decision trail in root-accessible durable storage. Record canonical role, adapter, session ID, agent ID, job ID, branch, head SHA, output path, and state when available. Do not require a Cursor Project tracker or an orchestration CLI. Use PR and CI event subscriptions when the host offers them. Do not add polling loops or relay routine status messages between agents.

#### Topology

- **One owner per PR.** Start a canonical `owner` through **Long-lived owner**. It is the only implementation writer on its branch. Only that owner pushes or rebases its assigned branch. The root authorizes topology changes and performs merges after independent verification. Closing or retargeting a base PR can orphan every PR above it, so it requires the root's call. Conflicted merges, chain rebases, and fixes go to owners, never coordinator code edits.
- **Fresh sessions for independent work.** Each brief carries the user's goal, write/no-touch paths, acceptance evidence, forbidden actions, standing orders, and upstream reports or accessible artifact pointers. Workers cannot read siblings' private context. Writers get isolated worktrees unless outputs are structurally disjoint. Work needing local authentication, simulators, installed control capabilities, or workspace history runs where those resources exist. Match effort and speed through the active adapter per **Delegation** in `poteto-mode`.
- **Sub-coordinators only for areas with many independent workers.** A root-started canonical `owner` tracks that area's briefs and returns one rollup and proposed child briefs. The root starts every participant; children never start children. Keep coordinator, track, and worker as logical roles, not nested runtime spawning. Use a rolling window around ten workers where useful and refill on completions rather than waiting on batches.
- **Reuse only state that is costly to move.** A checkout, uncommitted changes, or a running process can justify continuing the same session under the adapter. Independent work and fix rounds otherwise get fresh sessions with consolidated scope. Do not message a session merely to check liveness.
- **One independent verifier per PR.** Start canonical `reviewer` **Bounded session**, separate from the author and on a different model family when the runtime exposes supported routing. Disclose unavailable diversity rather than inventing model IDs. The root merges only after a pass covering the current patch and green CI at the current head, per **Shipping**.
- **Start with one unit.** Take it from brief through owner, verifier, and authorized merge before broad fan-out. For near-identical cheap units, the first ordinary unit is the pilot.

#### Supervision

- **Name the evidence in every brief.** Give an exact command and expected output, control-surface check, or artifact. Include the paths the worker may and may not write and actions it must not take. A unit without checkable evidence is not scoped.
- **Read the diff or artifact, not just the summary.** Green CI is input to a verdict, not the verdict. Behavioral work needs more than a type check. A new head requires a current verdict or evidence that **Shipping**'s patch-id rule carries it. Sample each sub-coordinator's briefs while work runs and repair instructions when a brief fails.
- **Reject scope drift.** Fix only discoveries blocking the program. Park unrelated findings rather than multiplying side projects across the fan-out.
- **Check live state before reporting.** Resolve the forge per **Opening a PR**, then use its current PR and check state, not the worker's last report. Account for every participant as done, replaced, or explicitly absorbed into another scope. Preserve reports and receipts as units finish, not at the end.
- **Replace stalled or looping sessions.** Judge pushes, PR activity, artifacts, and native runtime evidence, not status prose or transcript timestamps. Retry by cause: smaller scope after context or memory exhaustion, the same consolidated brief after connection loss, and another host-supported role/model after a tool failure. After two retries, drop the unit and replan. Reconcile late output against the current PR head and verdict before accepting it; salvage unique findings through a fresh session.
- **Ask only for a real decision or blocker.** Irreversible actions, product or preference calls no experiment settles, and a dead end surviving a replan reach the user. Rebase mechanics, CI flakes, review triage, and whether to keep going do not. Record gates durably and route work around them.

**Reply:** progress against the goal, each PR's live state and verdict with its link, what was dropped and why, decisions waiting on the user, and durable trail and handoff paths.
