### Autopilot-full

**You own verdicts and merges, never the implementation.** One owner carries each PR through merge-ready. Nothing lands until an independent swarm has proven the code that lands.

A verdict covers one patch. Green CI covers one head. Run a full swarm once, and again only for a major change. The patch-id rule in `skill://poteto-mode/playbooks/shipping.md` can carry a lane's result, but every new head needs green CI.

1. **Honor the operator's gates.** The autonomy grant covers only the queue. Operator-owned items and PRs outside it stop at merge-ready. A request to state the plan is not a go.
2. **Start one owner per PR and externalize its work.** Use the active adapter's **Long-lived owner** protocol with canonical `owner` role. Resolve the forge per **Opening a PR** once for the program. Use `gh` by default, or Origin when installed and able to resolve the repository. Never require Graphite. Each owner builds, opens its PR early so CI and bots run alongside the work, applies **unslop**, and reports code-ready after the root's **no-comments** review. The root starts review participants and Babysit watchers, relays frozen findings for fix-forward, and owns the authorized merge. Children never start participants.

   Rebase onto current trunk before the code-ready report and self-proof, so verification uses the landing base. Report every later head and merge-ready after self-proof, CI, and Babysit finish. Fix rounds stay on that base unless trunk conflicts, breaks CI, or lands a known concurrent change to the same files. Run repository checks for touched paths on the committed head before the code-ready push and before a later push that needs a verifier. Match each participant's effort and speed to the job per **Delegation** in `poteto-mode`.

   Assume the session or machine dies. Push soon after starting, keep a decision trail in root-accessible durable storage per **show-me-your-work**, and push each finished unit before starting the next. The root records every participant's canonical role, adapter, session/agent/job IDs, state, branch, head, report path, and a stuck-after runtime based on similar runs. Force-push only the assigned branch with `--force-with-lease` pinned to the SHA last pushed or explicitly taken over. If someone else pushed, stop and report to the root.
3. **Run independent owners in parallel off trunk, never stacked.** One writer per branch and isolated worktree. Serialize genuinely overlapping work. Start a fresh owner for each new queue item.
4. **Swarm-verify once at code-ready.** The root starts independent lanes per **swarm** at the reported SHA. Re-run gates, prove load-bearing behavior on the real surface through the installed control capability or a named driver, and audit the diff. The verdict is not clean without the live lane or before the root checks the merge-ready receipts. New behavior, a redesign, or a large new diff needs another full swarm. A rebase, conflict resolution, or minor fix gets one verifier at the new head. A wording-only change gets no new swarm, but still gets the checks and review its change requires.

   Block only for a demonstrated problem: a failing run at the head, a user-visible bug, a failed gate, or a shipped doc line the PR makes wrong. A problem already on the base does not block unless the PR copies or newly reaches it. Park other findings as follow-ups.
5. **The root merges only verified code tested on its landing base.** The grant and clean verdict authorize the root, not the owner. Operator-owned items still wait for the operator. Once swarm lanes have started, merge prep rebases onto current trunk, reports the head, and waits for green CI.

   Right before merging, fetch trunk and assess whether its changes affect the patch. Rebase and wait for CI if the landing code was never tested, including conflicts, files both sides changed, or changes to which checks run. A shared lockfile needs no rebase if a frozen install passes on the merge result and changed packages resolve as on the head. A failed install requires repair by rebase. If trunk changed a caller, dependency, or code the patch calls, run the patch's checks on the merge result and merge only on a pass. Otherwise merge. If trunk would force a third rebase past merge prep, hold and sequence the colliding work. Apply **Shipping** for the final merge and patch-id rules.
6. **Run the root layer.** Anything loosening a gate, such as a raised budget or allowlist entry, needs verifier proof and a fresh root countersign. Under a grant covering approvals, record that countersign where a lane can check it. A disabled or soft-failed check comes out. Never give or bypass an approval enforced by the forge.

   On the operator's go, arm an hourly root-controlled audit until no delegated work remains. Use the active adapter's event and wait evidence, not Cursor `/loop`, a self-rearming child, or a second polling loop. Re-read this playbook from the installed repository's trunk path and the durable objective on each tick. Have owners record missing heads or participants. Inspect every participant, including leaf lanes, by pushes, PR activity, and durable trail rows, not status text. An error, inability to start turns, or no new side effect past the recorded runtime means stuck. An owner with neither a push nor a trail row by the first tick is stuck. Someone waiting on the root or operator is not stuck; answer them. Replace a stuck session promptly with consolidated scope, reconcile late output against current state, and catch the operator up per **ketchup** only when the tick changed something for them. Keep a no-change tick quiet.
7. **Stand down immediately on the operator's stop.** Send every owner a zero-writes hold. Each reports its current state and keeps its brief until released.

**Reply:** catch the operator up per **ketchup**. Include each PR's state, head and verdict, what merged, which fresh owner took the next item, countersigns and reasons, operator gates, parked follow-ups, and links to PRs and decision trails.
